# Software Philosophy

0. **Blessed is the pessimist, for they hath backups.**

1. **Must solve genuine problems** — Not everything needs an app, and code is not always the solution.

2. **Software must work** — No shipping broken code.

3. **Expectations must equal reality** — No overhyping features. The fastest way to lose a customer is to sell a feature you do not have.

4. **Simpler is usually better** — Avoid dependency hell and unnecessary system resources.

5. **Complexity is better when it simplifies the user experience.**

6. **Default to vanilla** — Don't reach for a framework out of habit; use them only when they actually and elegantly solve a concrete problem to improve performance, reduce maintenance, and protect code longevity.

7. **If you think you can do it better yourself, you probably should** — Building an internal tool once often beats renting one for perpetuity.

8. **Done is better than perfect, but maintainable is better than fast.**

9. **Failing in predictable ways is better than failing in unique and unexpected ways.**

10. **Old code is not bad code** — Do not assume a newer language or newer framework is better than what already exists. Updating or changing should be done for a reason.

11. **Self-documenting code is a myth** — In-line documentation is important, but it can't give you the big picture understanding of how a code base works.

12. **Metrics are just numbers without context** — Remember the idea you are trying to measure. If you measure productivity by total number of commits, your engineers will do a great job creating a ton of commits.
